## デモのパイプライン概要

`demo_full_pipeline_0624.py` は以下の順序で処理を行います。

```
RealSense D405
  BGR 画像 (640x480 px, カラー)
  深度画像 (640x480 px, mm 単位)
        |
        | Step 1: カメラからフレームを取得
        v
  [DeepLabV3+]
        | Step 2: BGR 画像を入力して「どのピクセルがケーブルか」を推定
        v
  バイナリマスク (640x480 px, 0=背景 / 1=ケーブル)
        |
        | Step 3a: マスク内の全ピクセルの平均座標を計算
        v
  2D 重心ピクセル座標 (u, v) ← デバッグ表示用
        |
        | Step 3b: マスク + 深度画像でケーブル全体を 3D 点群に変換し、その平均を取る
        v
  ケーブル重心の 3D 座標 (X, Y, Z, 単位 mm, カメラ座標系)
        |
        | Step 4: 回転行列 R_camera_to_robot で座標系を変換
        v
  ケーブル重心の 3D 座標 (X, Y, Z, 単位 mm, ロボット座標系)
        |
        | Step 5: CtrlMoveXT で現在位置からの相対移動指令を送信
        v
  ロボットアームがケーブル重心の真上へ移動
```

> **注意:** TrackDLO によるキーポイント推定は現在コメントアウト中です。
> 代わりにケーブルの 3D 重心へ直接移動する方式を採用しています。

### 各ステップの補足

**Step 2: DeepLabV3+**
学習済みの深層学習モデルです。BGR 画像を受け取り、各ピクセルが「ケーブルである確率」を計算します。確率が 0.5 より大きければケーブル(1)、それ以下なら背景(0)と判定します。

**Step 3a: 2D 重心の計算 (`calc_pixelbased_mid_keypoint`)**
マスク内でケーブルと判定されたピクセルの行・列インデックスをそれぞれ平均し、2D 重心ピクセル座標 (u, v) を求めます。100 px 未満しか検出されていない場合はリトライします。この座標はデバッグ表示（赤丸）にのみ使われます。

**Step 3b: 3D 重心の計算 (`mask_depth_to_pointcloud` + 平均)**
カメラの内部パラメータ（焦点距離・光学中心）を使い、マスク内の全ケーブルピクセルをピンホール逆投影で 3D 座標 (mm) に変換します。深度値が 0 のピクセル（光沢・端部で計測不能）は除外し、残った全点の平均をケーブルの 3D 重心とします。

**Step 4: 座標変換 (`R_camera_to_robot`)**
3×3 回転行列でカメラ座標系のベクトルをロボットベース座標系に変換します。並進は含まれていません（キャリブレーション後に更新予定）。

**Step 5: ロボット送信 (`send_XT_to_robot` / `CtrlMoveXT`)**
現在位置からの相対移動量 (shift_x, shift_y, shift_z) をロボットへ送ります。Z 方向の移動量はホーム位置と安全下限から固定値で計算されます。

## パラメータ設定

`demo_full_pipeline_0624.py` の `main()` 関数冒頭にある変数を書き換えることで動作を調整できます。

### 基本設定

| 変数名 | デフォルト値 | 意味 |
|---|---|---|
| `weights` | `HERE / "mz07_demo_0624" / "weights" / "best_deeplabv3plus_cable.pth"` | 学習済みモデルのパス. best_deeplabv3plus_cable.pthは配布するファイルなので正しく配置できている必要がある。|


### ロボット設定（RobotConfig）
demo_full_pipeline_0624.py内の
`robot_cfg = RobotConfig(...)` の部分を書き換えます。

| フィールド名 | 単位 | 意味 |
|---|---|---|
| `dll_path` | — | OpenNR-IF.dll のパス |
| `ip_address` | — | ロボットコントローラの IP アドレス |
| `home_x_mm` | mm | 撮影位置となるホーム位置の X 座標 .ロボット座標系から見た絶対量。|
| `home_y_mm` | mm | 撮影位置となるホーム位置の Y 座標 .絶対量。|
| `home_z_mm` | mm | 撮影位置となるホーム位置の Z 座標 .絶対量。|
| `home_roll_deg` | 度 | ホーム位置での Roll 角 . 絶対量|
| `home_pitch_deg` | 度 | ホーム位置での Pitch 角. 絶対量 |
| `home_yaw_deg` | 度 | ホーム位置での Yaw 角. 絶対量 |


### コンベア高さの設定
demo_full_pipeline_0624.py内の
class RobotConfig の下に ` z_conveyor ` 変数が存在する。この値を書き換えて、ロボットから見たコンベアの高さをロボットに教える。
- **これはロボット座標系を基準としたときの**、コンベアの高さであり、この高さに向かってロボットツール先端を移動させる。設定を間違えるとコンベアとロボットハンドのツールが衝突するので、はじめはある程度余裕を持って大きな値を設定する。
- この値を設定する際には実際にロボットを手動操作し、軸モニタに表示された値を入力する。
- 動作確認の際には、くれぐれも低速再生するように注意してほしい。この値の設定を間違えるとLGのコンベアに衝突してしまう。


### デモ用の微調整用パラメーター
demo_full_pipeline_0624.py内の
main() 関数終盤(648行目)に`demo_shift: np.ndarray = np.array([40.0, -20.0, 0.0])` という行がある。
- この中の配列`[40.0, -20.0, 0.0]`の部分は順に、ツール座標系目線のx, y, z成分のシフト量である。この値を変更して**ツール座標系基準で** ロボットハンドの最終到達位置を微調整できる。単位はmm である。
- 今回のデモでは問題ないと思われるが、座標変換を介していない点に注意する。

### 制御装置の設定/注意点
- 手始めに仮想安全策の設定を行ってから作業すること。特にPythonスクリプト内のパラメーターの設定は非常に間違えやすいので必要である。
- ロボット本体の根本に基準となるロボット座標系を登録できていることを確認する。スクリプト内の数値には絶対量と相対量が混在し、非常に間違えやすいためトラブル回避のために必要である。
- pythonスクリプトによりロボットの動作を行う場合は外部起動をONに設定する必要がある。
- 動作前にツール座標の設定が必要である。ロボットハンドの爪の左右どちらかを基準に選ぶ。デモ用の微調整はPythonスクリプト内で行う。
- D:/WORK/PYTHON.CON 内に実行するスクリプトを指定すると、ティーチングペンダントからPythonスクリプトを実行できる。

## ロボット据え付け時の注意（本番）
- **デモの際には、ケーブルは S 字または直線に近い形状で設置する。大きくケーブル全体が折れるような変形には対応できない。**
- 動作確認・学習データを収集したときと同様の背景・照明条件下でデモを行う。床や背景色の変化に非常に敏感なので注意する。
- 他の無関係なケーブルはできる限りカメラに映らないようにする。誤認識の原因となる。

## 目標位置の応急補正

`demo_full_pipeline_0624.py` の **645 行目** にある `demo_shift` を書き換えることで、
推定された目標位置にオフセットを加えることができます。

```python
# demo_full_pipeline_0624.py  line 645
demo_shift: np.ndarray = np.array([40.0, -20.0, 0.0])  # mm, tool coordinate
```

- 値の意味: `[X方向オフセット, Y方向オフセット, Z方向オフセット]`（単位: mm、ツール座標系）
- カメラとロボットのキャリブレーションが未完了で位置がずれる場合に、ここを調整することで応急処置的に補正できます。
- キャリブレーション完了後はこの値を `[0.0, 0.0, 0.0]` に戻してください。
